# Mermaid 规则

本文件是 Mermaid 图表的详细规范。核心 OutputFormat 中只保留关键规则，详细规则以本文件为准。

---

## 一、使用原则

架构图、流程图、模块关系、依赖关系、数据流、状态机和时序关系优先使用 Mermaid。

Mermaid 必须服务于理解，不得为了"看起来专业"而强行绘制。

核心原则：

> **图负责建立结构，文字负责解释结构。**

只有当图能够明显降低理解成本时才绘制。不要为了看起来丰富、增加内容、增加视觉效果而强行画图。

优先绘制：

- 项目总体架构
- 模块依赖
- 核心业务流程
- 核心数据流
- 关键调用关系
- 线程/进程关系
- 时序关系
- 状态变化

如果 Mermaid 无法准确表达，应使用普通 Markdown 列表或标准代码块。

禁止使用图片承载：架构图、流程图、数据流、依赖关系、状态机、时序关系。

---

## 二、图表方向

知识地图优先使用 `graph LR`（横向展开）：

```mermaid
graph LR
    A[用户空间] --> B[系统调用]
    B --> C[VFS]
    C --> D[字符设备]
```

流程、调用链、生命周期等其他图优先使用 `graph TD`：

```mermaid
graph TD
    A[开始] --> B[初始化]
    B --> C[运行]
```

模块架构图和数据流图也可以使用 `LR`。节点较多时，根据实际可读性调整方向。如果一个方向导致连线大量交叉，应尝试其他方向或拆分图表。

---

## 三、基础图表示例

### 流程图

```mermaid
graph TD
    A[Application] --> B[Service]
    B --> C[Core]
    C --> D[Platform]
```

### 数据流

```mermaid
graph LR
    A[Input] --> B[Buffer]
    B --> C[Process]
    C --> D[Output]
```

### 时序图

```mermaid
sequenceDiagram
    participant A as Application
    participant B as Service
    participant C as Core

    A->>B: Request
    B->>C: Process
    C-->>B: Result
    B-->>A: Response
```

---

## 四、图表类型选择

| 图表类型 | 适用场景 |
| --- | --- |
| `graph` | 流程、模块关系、层级和数据流 |
| `sequenceDiagram` | 对象之间的时序交互 |
| `stateDiagram-v2` | 状态和状态转换 |
| `classDiagram` | 类、结构体和类型关系 |
| `erDiagram` | 实体及其关系 |
| `gantt` | 任务和时间安排 |
| `mindmap` | 思维导图和知识组织 |

---

## 五、连线规范

| 语法 | 含义 |
| --- | --- |
| `-->` | 普通方向关系 |
| `-.->` | 虚线关系 |
| `==>` | 强调关系，使用前确认渲染器支持 |
| `-->|说明|` | 带标签的方向关系 |
| `---` | 无方向连线，使用前确认图表类型支持 |

推荐使用最简单、兼容性较好的连线语法。

连线标签应遵循：文本简短、语义清晰、避免复杂特殊字符、避免过长句子、不嵌入大量代码。

当大量连线交叉时，应调整图表方向、节点顺序、简化关系、拆分图表，或使用文字说明补充。

---

## 六、时序图规范

时序图应明确声明参与者，并保持消息文本简洁。

```mermaid
sequenceDiagram
    participant App as 应用程序
    participant Driver as 驱动程序
    participant Device as 设备

    App->>Driver: 发送控制请求
    Driver->>Device: 操作硬件
    Device-->>Driver: 返回结果
    Driver-->>App: 返回处理结果
```

要求：参与者名称清晰、数量不宜过多、消息方向准确、内容简短、调用顺序符合逻辑、避免在消息中嵌入复杂代码、复杂说明放在图表外部、异常流程应明确标识。

---

## 七、状态图规范

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Running: start
    Running --> Stopped: stop
    Stopped --> Running: restart
    Running --> Error: failure
    Error --> Idle: reset
```

要求：状态名称清晰、转换条件简洁、不将大量业务逻辑写入转换标签、状态过多时拆分、转换与正文描述保持一致。

---

## 八、大图拆分

每张图只表达一个主要问题。

当出现以下情况时，应拆分图表：

- 节点数量过多
- 连线大量交叉
- 节点文本过长
- 图表缩放后难以阅读
- 同时表达多个不同层次的问题
- 图表包含过多无关细节
- 图表无法在目标编辑器中正常显示
- 读者无法快速识别主要流程

建议每张图聚焦一个子主题，通常控制在约 5～8 个主要节点。

推荐的拆分方式：

```text
总体架构图 + 模块依赖图 + 核心业务流程图 + 关键数据流图
```

不要为了"一张图看完所有内容"而制作无法阅读的巨型图。

---

## 九、流程与架构表达

当存在明显的层级关系时优先使用 Mermaid：

```mermaid
graph TD
    A[Application] --> B[Business]
    B --> C[Core]
    C --> D[Platform]
    D --> E[Operating System]
```

当关系复杂时，拆成：总体架构图 + 模块依赖图 + 核心业务流程图 + 关键数据流图。

---

## 十、节点文本规范

### 1. 禁止 HTML 换行标签

禁止在节点中使用 `<br>` `<br/>` 等 HTML 标签。需要分隔内容时使用空格。

错误：

```mermaid
graph TD
    A["用户空间<br/>insmod / rmmod"]
```

正确：

```mermaid
graph TD
    A["用户空间 insmod / rmmod"]
```

### 2. 禁止 Unicode 箭头

不要使用 `→` `←` `↑` `↓` `⇒` `⇐` 等 Unicode 箭头表达节点关系。流程方向通过 Mermaid 连线表达。

错误：

```mermaid
graph TD
    A["Lexer → Parser → AST"]
```

正确：

```mermaid
graph TD
    A["输入"] --> B["处理"]
    B --> C["输出"]
```

### 3. 禁止中文标点

节点标签和消息文本中禁止使用中文标点（`，` `：` `。` `；`等），需要分隔时使用空格。

错误：

```mermaid
graph TD
    A["就绪，等待文件打开"]
```

正确：

```mermaid
graph TD
    A["就绪 等待文件打开"]
```

### 4. 特殊路径必须用引号

节点文本以 `/` 开头时必须使用双引号。包含 `/` `@` `=` `[` `]` `(` `)` 等特殊字符时也建议用双引号。

错误：

```mermaid
graph TD
    A[/proc/device-tree/]
```

正确：

```mermaid
graph TD
    A["/proc/device-tree/"]
    B["soc@3000000"]
    C["CONFIG_VIDEO=1"]
```

### 5. 节点名称清晰简洁

使用清晰、具体的名称，避免长句，不将大量代码放入节点，一个节点表达一个主要概念，复杂说明放在图表外部。

---

## 十一、代码块嵌套规范

展示 Mermaid 代码示例时，外层代码块用 4 个反引号，内层用 3 个：

````markdown
```mermaid
graph TD
    A["开始"] --> B["结束"]
```
````

注意：内外层反引号数量必须区分，不让外层提前结束，不在代码块开始位置添加无关属性。

---

## 十二、渲染失败时的处理

如果 Mermaid 图表无法正常渲染，按以下顺序排查：

1. 检查代码块是否使用 `mermaid` 标识
2. 检查图表类型是否正确
3. 检查图表方向是否正确
4. 检查节点和连线语法
5. 检查括号和引号是否完整
6. 移除不必要的特殊字符
7. 移除 HTML 标签
8. 缩短节点文本
9. 减少节点数量
10. 简化连线关系
11. 拆分复杂图表
12. 更换为兼容性更高的图表类型
13. 必要时使用 Markdown 列表、表格或纯文本替代

如果简单结构可渲染而复杂结构不行，应逐步增加节点和连线定位问题。

不得在没有实际验证的情况下声称 Mermaid 图表一定可以正常渲染。

---

## 十三、替代方案

当目标环境不支持 Mermaid 或图表无法清晰表达时：

### 列表表达流程

```text
1. 打开设备
2. 配置采集参数
3. 启动数据采集
4. 读取数据
5. 处理数据
6. 输出结果
```

### 表格表达模块关系

| 模块 | 输入 | 输出 | 作用 |
| --- | --- | --- | --- |
| 采集模块 | 硬件数据 | 原始数据 | 获取设备数据 |
| 处理模块 | 原始数据 | 处理结果 | 执行数据处理 |
| 输出模块 | 处理结果 | 输出数据 | 展示或保存结果 |

### 纯文本表达架构

```text
应用层
  |
服务层
  |
驱动层
  |
硬件层
```

---

## 十四、输出前检查

每个 Mermaid 图输出前检查：

```text
代码块是否使用 mermaid 标识？
是否存在 HTML 标签？
是否存在 Unicode 箭头？
是否存在容易导致解析失败的中文标点？
是否正确处理 / 开头的路径？
特殊字符是否需要双引号？
图的方向是否合适？
连线语法是否正确？
节点数量是否过多？
图与正文是否一致？
渲染失败时是否有替代方案？
```
