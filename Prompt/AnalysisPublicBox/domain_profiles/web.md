# Web Domain Profile

适用：

- 前端应用
- 全栈 Web 应用
- 单页应用（SPA）
- 服务端渲染（SSR）
- Web 组件库
- 前后端分离项目

---

## request_response_flow

【重要度：5｜必须阅读】

分析实际请求响应流程：

浏览器/客户端
↓
HTTP 请求
↓
路由
↓
控制器/Handler
↓
服务层
↓
数据访问
↓
响应

只保留项目真实存在的阶段。

---

## routing_analysis

【重要度：5｜必须阅读】

分析：

- 路由定义位置
- 路由匹配规则
- 动态路由
- 嵌套路由
- 路由守卫/中间件
- 路由懒加载

仅存在路由系统时分析。

---

## component_architecture

【重要度：4｜强烈建议】

分析：

- 组件层级
- 组件通信方式（props / event / store / context）
- 状态管理方案
- 复用策略

仅前端项目存在组件时分析。

---

## state_management

【重要度：4｜强烈建议】

分析：

- 全局状态
- 局部状态
- 状态变更流程
- 持久化策略

仅存在状态管理时分析。

---

## api_integration

【重要度：4｜强烈建议】

分析：

- API 调用层
- 请求拦截
- 响应处理
- 错误处理
- 鉴权注入

---

## rendering_model

【重要度：5｜必须阅读】

分析项目采用的渲染方式：

- CSR（客户端渲染）
- SSR（服务端渲染）
- SSG（静态生成）
- ISR（增量静态再生成）
- 混合模式

必须依据实际构建配置和源码确认，不得根据框架名称假设。

---

## static_asset_pipeline

【重要度：3｜按需查阅】

分析：

- 打包工具
- 资源处理
- 代码分割
- Tree Shaking

仅存在前端构建流程时分析。
